一、GitHub Pages 是什么

GitHub Pages 是 GitHub 免费提供的静态网站托管服务。只要你的仓库名叫 <用户名>.github.io，仓库里的静态文件就会自动发布到 https://<用户名>.github.io。

它有三个关键特点：

  • 完全免费，自带 HTTPS
  • 只能托管静态文件，不能跑后端和数据库
  • 对个人博客、项目文档来说完全够用

博客的本质就是一堆 HTML 文件，所以静态托管正是它最合适的归宿。

八、踩坑记录

这些是我实际遇到过的坑，提前知道能省不少时间：

1. 部署后访问 404

刚部署完 Pages 需要构建，等一两分钟再刷新，不要急着连续重推。

2. Permission denied (publickey)

公钥没加对地方，或者加到了另一个 GitHub 账号。用 ssh -T git@github.com 看返回的用户名是不是你自己的。

3. 页面能打开但样式全丢

_config.yml 里的 url 和实际访问地址不一致导致的，改成 https://<用户名>.github.io（末尾不带斜杠）。

4. 网络连不上 GitHub

国内网络访问 GitHub 的 443 端口时不时会抽风，但 22 端口（SSH）通常稳定得多。这也是推荐 SSH 方式部署的原因之一。

5. 分支名不一致

新建仓库默认分支可能是 main，而老仓库和很多教程用的是 master。deploy 里的 branch 必须和仓库实际分支一致，否则会推到空分支导致 404。

九、进阶建议

  • 换个好看的主题：官方主题站 hexo.io/themes 有几百个，下载后放进 themes/ 目录，改 _config.yml 的 theme 字段即可
  • 源码也备份一份：构建产物可以随时重新生成，但 source/_posts/ 里的文章是唯一的，建议把源码推到一个私有仓库（Gitee 或 GitHub 私有库都行），形成「源码一个仓、产物一个仓」的双仓库结构
  • 绑定自定义域名：在 source/ 下放一个 CNAME 文件写入域名，再去域名服务商加一条 CNAME 记录指向 <用户名>.github.io

祝写作愉快。
